# 同時段容量設定驗收

Admin 從「後台 → 設定」修改「同時段課程上限」，可填 1–100 的整數。未儲存過設定時預設為 4 堂，不需要搬移既有資料。儲存後後端立即採用新值，已開啟的行事曆請重新整理以更新提示。

測試需使用不同學生與不同教練，且每位學生都有足夠堂數；同一人仍受衝堂限制。

| 操作 | 預期結果 |
| --- | --- |
| 上限 4，同時段登記 4 堂，再嘗試第 5 堂 | 前 4 堂成功，第 5 堂顯示已達 4 堂上限；行事曆在 3 堂時顯示剩 1 堂、4 堂時顯示額滿 |
| 將上限改為 5，重新整理行事曆並登記第 5 堂 | 顯示新容量且可成功預約 |
| 已有 4 堂的時段，將上限調為 2 | 原有 4 堂保留，仍能編輯原時段課程；不能新增或將其他時段的課程移入 |
| 上述時段取消 3 堂，再移入一堂 | 剩 1 堂時可再接受一堂，達 2 堂後停止接受 |
| 兩個管理視窗同時搶最後一個名額 | 只有一筆成功，失敗預約不留下占堂或課程 |
| 輸入 0、負數、小數或超過 100 | 無法儲存，API 也拒絕 |
| 使用教練／學生帳號 | 看不到管理設定入口，直接存取設定 API 也被拒絕 |
| 建立循環課程，其中一天已滿 | 整批拒絕，不建立部分課程 |

自動測試：`tests/scheduling-settings.test.ts`，使用記憶體資料庫替身驗證實際 service，包含設定與預約同時發生時的交易重試。正式資料庫與瀏覽器操作仍依上表驗收。
