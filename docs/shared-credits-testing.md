# 共用方案與儲值作廢：操作及驗收

## 功能規則

- 同一筆儲值可由多位學生共用，最多 20 人。24 堂就是共同 24 堂，不會變成每人 24 堂。
- 新增儲值時可選一位共用會員；更多會員可在「儲值紀錄 → 加入共用會員」加入。
- 既有儲值也可加入共用會員，已預約或使用的堂數不會重設；新增會員可使用剩餘可預約堂數。
- 目前僅支援加入共用會員，不提供移除或轉移所有權。
- 每堂課仍只有一位實際上課學生，打卡與個人行事曆仍以該學生為準。
- 同方案有多筆儲值時，沿用最早到期優先的分配方式，包含個人與共用儲值；不需要手動分配 A、B 各幾堂。
- 會員畫面的「總剩餘／已預約／尚可預約」包含共用方案及其他共用會員占用的堂數；不是個人上課堂數統計。不同會員的共用餘額不可加總當成全店總堂數。
- 其他帳號操作後，重新整理會員頁面可取得最新餘額。
- 僅管理員能加入共用會員或作廢。作廢針對整筆儲值，需填原因，保留原紀錄及反向流水，不處理金流退款。
- 僅「從未預約、從未扣堂」的儲值可作廢。取消、未完成或將預約改到別筆儲值後，也不能作廢曾被使用的原儲值。
- 舊資料缺少完整的歷史使用標記，無法證明從未預約，因此顯示原因並禁止作廢；仍能正常共用、預約、取消及扣堂。不要手動將舊批次標記成從未預約。

## 準備

建議在測試環境使用管理員、教練、學生 A／B／C。準備「測試 1對1 24堂」及「測試 1堂」方案，讓測試會員沒有其他同方案堂數，以免自動分配到其他儲值。用不同瀏覽器或無痕視窗登入不同帳號。

操作入口：管理後台 → 會員管理 → 儲值堂數／儲值紀錄。

## 主要驗收

| # | 實際情境及操作 | 預期結果 |
| --- | --- | --- |
| 1 | 替 A 儲值 24 堂，選 B 為共用會員 | A、B 都顯示共用 24、已預約 0、可預約 24；C 沒有此方案。儲值紀錄顯示 A、B。 |
| 2 | 分別替 A、B 預約不同時段各一堂 | 兩人的共用方案都顯示剩餘 24、已預約 2、可預約 22。 |
| 3 | B 報到，課程結束後由教練確認完成 | 兩人的共用方案都顯示剩餘 23、已預約 1、可預約 22。教練報表記錄上課學生 B，一堂只計算一次。 |
| 4 | 管理員取消 A 的預約 | 兩人的共用方案都顯示剩餘 23、已預約 0、可預約 23。 |
| 5 | 替 A 再預約一堂；結束後選「未完成」並填原因 | 釋放占用，剩餘堂數不扣除；A、B 可再次使用釋放的堂數。 |
| 6 | A 個人持有一筆已有使用紀錄的舊儲值，從紀錄加入 B | 原剩餘與占用維持；A 從個人改顯示共用，B 取得相同共用餘額。A 原預約仍能完成或取消。 |
| 7 | A、B 共用測試 1 堂，先替 A 預約，再編輯學生為 B 並重新選擇同方案 | 即使可預約為 0，也能成功改人；占用仍是 1，之後完成或取消都只處理一次。 |
| 8 | 原預約由共用方案改用另一個個人方案 | 原共用方案釋放一堂、新方案占用一堂，原儲值仍不能作廢。 |
| 9 | A、B 共用只剩一堂；兩個管理視窗同時送出不同時段的預約 | 最多一筆成功，另一筆顯示堂數不足；沒有負餘額，也沒有失敗預約的殘留課程。 |
| 10 | 可預約 3 堂，嘗試建立 4 次循環預約 | 整批失敗，不建立部分課程；改成 3 次可成功。 |
| 11 | B 已有同方案個人堂數，又加入 A 的共用方案 | 畫面分開標示個人／共用；預約按到期日分配，不複製或重複計算同一筆共用堂數。 |
| 12 | B 打開自己的行事曆或報到頁 | 只能看到／報到自己的課程；不能因共用方案而替 A 打卡。 |

完成測試可使用管理員建立過去日期的課程，補登報到後再確認完成，避免等候實際下課；一般會員自行打卡仍受原本時間限制。

## 作廢驗收

每個案例使用獨立儲值，避免前一個案例已留下預約紀錄。

| # | 操作 | 預期結果 |
| --- | --- | --- |
| 13 | 新增一筆完全未預約的個人儲值，從儲值紀錄按「刪除／作廢儲值」 | 要求原因與確認；成功後扣回該筆全部堂數，保留已作廢紀錄。其他儲值不受影響。 |
| 14 | 新增一筆完全未預約的共用儲值，從 A 或 B 的紀錄作廢 | 確認畫面提醒影響所有共用會員；成功後 A、B 都不能使用該筆餘額。 |
| 15 | 有已預約、已報到或已完成的課程 | 作廢按鈕不可使用並顯示原因；直接呼叫 API 也會拒絕。 |
| 16 | 先預約，再全部取消或確認未完成 | 即使堂數恢復原額，也不能作廢，顯示曾被預約的原因。 |
| 17 | 開啟未使用儲值的作廢確認，同時從另一視窗預約 | 只有預約或作廢其中一方成功；後端重新檢查狀態，不依賴過期畫面。 |
| 18 | 重送同一筆作廢請求，或重新開啟已作廢紀錄 | 不重複扣堂；紀錄維持已作廢，不能再加入共用會員或預約。 |
| 19 | 作廢原因留白 | 不能送出，API 也拒絕。 |
| 20 | 查看缺少完整歷程的舊儲值 | 顯示「舊儲值缺少完整預約歷程…」，不允許作廢。 |
| 21 | 教練／學生嘗試呼叫加入共用、查看儲值明細或作廢 API | 回覆無權限，資料不變。 |

## 自動驗證及範圍

執行 `npm test`、`npm run lint`、`npx tsc --noEmit --incremental false`、`npm run build`。

`tests/shared-credits.test.ts` 呼叫實際 service，使用記憶體資料庫替身檢查交易原子性、讀寫順序、競爭重試及業務結果，無須正式資料庫憑證。這不是 Firestore Emulator 或正式環境的端到端測試；上表是實際登入與資料庫環境的驗收清單。
